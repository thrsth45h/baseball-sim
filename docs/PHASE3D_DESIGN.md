## 1. 今回決める範囲

**固定した人工の打球軌道について、守備者1人が飛行中に同じ水平位置へ届き、その時の球の高さが指定範囲に入る時刻があるかを求める。** 最初の地面到達だけを調べた[Phase 3c](PHASE3C_DESIGN.md)から、途中の機会へ対象を広げる。

出力は到達条件を満たす時刻区間の集合と最初の時刻の包囲。真の全軌道を既知とする、理想化した幾何的な存在判定である。経路選択・知覚・予測誤差・実際の捕球動作/成功確率・公式アウト/安打を生成しない。「条件を満たす経路が存在する」と「選手がその経路を選べる」を区別する。

空気抵抗・風・回転・球場・壁・身体の水平半径・加減速・複数守備者・地面反発/転がり・送球・走塁も含めない。実データ/旧3b・能力1〜20・ゲーム本体への接続、学習・新規データ取得は行わない。旧3cを含む研究コード・結果・契約は維持する。

## 2. 理由・反例・代替案

3cの地面到達点への距離余裕が負でも、途中で同じ位置を通る場合がある。人工例x(t)=10t、z(t)=1+10t−gt²/2、守備者(20,0)・移動速度0では、t=2に高さ1.3867mを通る。高さ上限1.5mなら途中の幾何条件を満たすが、地面到達点は約21.35mである。この反例を3cの不具合とせず、異なる問いとして扱う。

| 候補 | 利点・反論と判断 |
|---|---|
| 地面到達の余裕だけを捕球判定へ読み替える | 追加計算は少ないが、上の反例を誤判定する。採用しない |
| 33表示点や固定刻みで途中を探索する | 実装は容易だが、点の間の短い機会や接線での単一時刻を見落とす。主判定には採用しない |
| 二次不等式を連続時間で解く | 境界を明示でき、地面との違いを検証できる。数値の慎重な扱いが必要。今回の推奨 |
| 捕球確率・認知・全守備を一度に作る | ゲームに近づくが、未較正の仮定を同時に増やす。別設計へ保留 |

無空気・一定重力の運動方程式は[OpenStax](https://openstax.org/books/university-physics-volume-1/pages/4-3-projectile-motion)の仮定と同種である。MLBの捕球指標は実際の機会から確率を扱う。[MLB公式](https://www.mlb.com/glossary/statcast/catch-probability) 本案はその確率モデルの再現や実測検証ではない。

## 3. 人工入力と数値の意味

座標は3cと同じ、ホーム地面原点、右+X・中堅+Y・上+Z。初期位置は(0,0,h)。3d専用の`Flight`は**直交する3成分の初速**を受ける。EV/LA/方位の生成器・変換器は今回作らない。三角関数の丸めと到達境界の検証を分けるためで、既存3cの`Launch`契約は変更しない。

| 型・入力 | 合成検証範囲 | 単位 |
|---|---|---|
| Flight.vx_mps / vy_mps / vz_mps | 各−50以上50以下 | m/s |
| Flight.height_m | 0超5以下 | m |
| ReachFielder.initial_x_m / initial_y_m | 各−1000以上1000以下 | m |
| ReachFielder.move_speed_mps | 0以上20以下 | m/s |
| ReachFielder.reaction_s | 0以上30以下 | s |
| ReachFielder.max_height_m | 0超5以下 | m |

範囲・高さ上限・反応仮定は**研究用の仮設定**。実際の人体限界・能力係数・観測された分布ではない。全入力を有限binary64へ正規化し、bool・文字列・NaN/Infinity・範囲外・未知フィールドを拒否する。値の来歴が人工であることを一般の数値だけから証明できるわけではなく、固定runnerと入力schemaの情報境界を検査する。

正規化後のbinary64値を`as_integer_ratio`相当の正確な有理数として解釈する。g=9.80665は十進の有理数`980665/100000`とする。三角関数を含まないこの係数系での到達性を判定する。**厳密な符号判定とは、この人工係数系に対する意味であり、物理的正確さの証明ではない。** 3cの浮動小数点計算と丸め順序まで同一の新実装にはしない。

## 4. 到達条件

```text
x(t) = vx*t
y(t) = vy*t
z(t) = h + vz*t - g*t*t/2
T = z(t)=0 の唯一の正根
tau = reaction_s, s = move_speed_mps, H = max_height_m
K = {t | tau <= t < T, 0 < z(t) <= H,
          (vx*t-fx)^2 + (vy*t-fy)^2 <= s^2*(t-tau)^2}
```

h>0なので0≤t<Tではz>0。Tは真の人工多項式の根として比較し、丸めた3cの`ground.time_s`を境界に代用しない。球と守備者の水平半径は0である。反応後は速度s以下でどの方向にも移動/停止でき、障害物なしなので、移動可能領域は中心F・半径s(t−tau)の円盤となる。Kは単一時刻への経路存在の集合であり、同じ1本の守備経路がKの全時刻で球と一致するという意味ではない。

**反応時刻より前は、既にその位置に居ても機会に含めない。** 反応時刻以後は移動速度0でも位置が一致すればよい。これは捕球への準備もtauまで完了しないという人工仮定で、3cの距離予算の意味を変更しない。tau=0で初期位置と高さが合えばt=0を含む。打撃瞬間の実際の捕球規則を表すものではない。

地面t=Tは必ず除外する。高さ上限と移動距離の等号は含む。単一時刻だけの一致も幾何的機会として含むが、有限の捕球時間や成功確率は与えない。H>0かつh>0の下で、Kが空でなければその最初の時刻は含まれる。

水平の条件は、t≥tauの下で次の二次不等式と同値。

```text
A = vx*vx + vy*vy - s*s
B = -2*(vx*fx + vy*fy) + 2*s*s*tau
C = fx*fx + fy*fy - s*s*tau*tau
Q(t) = A*t*t + B*t + C <= 0
```

二乗前の半径が非負であることを時間制約で保証する。A=0の一次式、A=B=0の定数式、判別式0/正/負、上に凸/下に凸、速度0、反応0を別に扱う。z≤Hには上昇側と下降側の二つの区間があり得る。一つの下降時刻だけの検査で全体を代表しない。

## 5. 解法・結果の契約

有理数係数で高さ・水平・時間の条件を解き、**区間の和集合を交差**する。二次根は多項式・根の順序・有理数の包囲で表し、同じ根を正確に識別する。係数の零・判別式・有理点での符号は有理演算とし、共通根の等号は多項式の共通因子等で判定する。根の順序を浮動小数点の近さだけで決めない。今回の入力範囲ではz(16)≤5+50×16−g×16²/2<0なのでT<16秒であり、関連する正の根の隔離は[0,16]の有界時間内で行える。

異なる根は有理包囲を二分して順序を確定する。1比較/端点につき最大512回の精密化とし、決定できなければ`indeterminate`と理由を返す。これは研究用の停止上限で、失敗/非到達に置換しない。離散時間走査・密な点の一致・精度を変えて同じ値になったことだけを、空集合や根の順序の証明としない。εを身体半径や判定式に足さない。

| status | feasible | 出力 |
|---|---|---|
| resolved | true | Kの全区間と端点の開閉、最初の時刻の根/有理値の識別子と包囲 |
| resolved | false | 証明された空集合、区間空、最初時刻null |
| indeterminate | null | 理由、未解消の比較・計算上限。完全な区間/最初時刻はnull |

各端点は有理数そのもの、または整数係数の正規化多項式（原始・最高次係数正）と相異なる実根の昇順index（0始まり）で識別する。有理根は既約分数へ正規化し、二重根を二つの時刻として数えない。有理包囲は既約分数の文字列組で保存し、指定された根を含むことを確認する。根の表示包囲幅は1e−12秒以下（有理数なら幅0、無理数の単一時刻も包囲を持つ）。**この幅で別の端点を合体させない。** 順序・等号と開閉は識別子/厳密比較で決め、包囲が重なることと等号を混同しない。

公開する包囲は比較用の精密化キャッシュと分離する。同じ根IDに対し、[0,16]からの固定二分手順で、対象根を一意に含み、かつ幅≤1e−12秒を初めて満たす包囲を生成する。近い別根との比較でさらに精密化しても公開包囲を変えない。これにより、比較/実行順・単独/一括で同じ根の出力が変わらない。

丸めた中央時刻や表示座標は補助表示であり、そこが必ずKに入るwitnessとは呼ばない。特に単一時刻の二重根で丸め値を再代入して非到達へ覆さない。t=Tだけの一致は空。固定の通常例は全てresolvedを受入れ条件とし、未解消を隠して集計しない。入力不正は例外、計算の未解消はstatusとして区別する。

区間は開始時刻順で重複のない最大の連結区間へ正規化する。接する二つの区間は、その接点が少なくとも一方に含まれるときだけ結合する。単一時刻は両端同じ根・両端closedで表し、空区間を出力しない。正規化も表示丸めではなく厳密な端点比較で行う。

## 7. 受入れ検証

1. 有理数の手計算でdrop・速度等号・反応/地面等号・高さ等号・t=0を検証。高精度の別方式で全20例の区間数・端点開閉・最初時刻包囲を照合する。根の包囲が多項式の指定根を含むことも検証し、同じ計算式の写しだけで独立照合にしない。
2. stationaryの接線による単一時刻、Qの一次/定数・判別式0/正/負・Aの正負・共通根・ほぼ等しい別根を検証。ground_onlyはfalse、single_instantとnarrow_ground_windowはtrue、two_height_windowsは区間二つを要する。空集合の認定を点走査に依存させない。
3. 512精密化で解消できない場合を注入/既知の難例等で検査し、indeterminateのfeasible=nullと理由を確認。低いテスト用上限と本番上限を混同しない。固定20例の未解消0を報告する。
4. 移動速度↑・反応時間↓・高さ上限↑でKが狭くならない。最初時刻の単調性だけでなく集合の包含を検査する。左右反転/90度回転では守備者座標も変換して区間が一致。固定の対称例は双方が非空であることも確認し、空集合同士の一致だけで済ませない。守備者変更で球の式/地面根が変わらない。
5. 旧3cの同じ成分に対応する自由落下/水平/鉛直等を比較し、位置/地面時刻が既存の数値許容範囲内で整合する。3cの地面余裕と途中の機会が異なる反例を保持し、3cを変更しない。EV増加に対する捕球難度など、未定義な単調性を課さない。
6. 単独/一括/実行順変更で同じ結果。RNGを使用しない。旧raw・モデル・Parquet等を新runが開かず、hc/events/安打アウト/能力値/未知フィールドを入力として拒否することを監視する。
7. 既存全497テストと新規必要テスト、Python3.11/3.12 PR CIを実行。旧コード・出力・索引は変更せず、root READMEの案内追加だけを旧ファイル変更の例外とする。依存パッケージは増やさず標準ライブラリで実装する。
8. 二つの新出力先でrunし、実行時間/資源記録とそれを含むhashを除く4主要成果物のバイト一致。責任者は別worktreeで全コード・テスト・独立期待値・再実行と旧hashを確認し、修正はworkerへ直接依頼する。
