## 2. 再開時に見つかった反例と訂正

Phase 2aの実際の対象は、処理済み適格入力のうち、`swinging_strike / swinging_strike_blocked / foul / foul_tip / hit_into_play` の5つのdescriptionに該当する行である。これを「通常スイングだけ」とした説明は保証できない。旧y_swingとの一致も、その独立した確認にはならない。

責任者はD6で選定済みのraw `2023/2023-03-30_2023-04-02.parquet` を、処理済み2023年入力と `game_pk / at_bat_number / pitch_number` で一対一結合した。責任者とは別の計算で実装workerも同数を確認した。個票・選手名・ID一覧は公開しない。

| この限定標本で確認したこと | 件数 |
|---|---:|
| rawの元行 | 14,707 |
| 処理済み適格行と対応 | 14,629 |
| 対応しないraw行 | 78 |
| 適格行内のhit_into_play | 2,480 |
| そのうちeventsがsac_buntで始まる | 4 |
| そのうちdesにfoul territoryがあり、events=field_out | 62 |
| 上の62件のうちdesにpops outもある | 56 |

二つの診断群の重複は0件。現行実装は両群とも `y_swing=1 / y_contact=1 / outcome_tag=fair_in_play` に含める。接触二値という割当とは矛盾しないが、`fair_in_play` は**hit_into_playに付けた既存タグ名であり、フェア打球を保証しない**。バント固有descriptionを除外しても、犠牲バント等のhit_into_playが残る。

- raw SHA-256: `407f107a8e755f44fc5b066f87f5d9f2858f9f85995c0e08bc28bc6191c808cf`
- processed/2023/pitches.parquet SHA-256: `00ad8df8146acbca173f59dbf2fc734606cc9d3cd9ef24d33dbb3af7a703b303`

自由記述・記録イベントは今回の反例を示す証拠であり、独立に裁定した全投球の物理的な真値ではない。この1 chunkから全年度の混入率を推定しない。78行の非対応も自動的にデータ欠損と断定しない。元の前処理で対象外になる行を含む。

公式CSV説明はdescriptionを投球の結果、eventsを打席結果の記述としているが、hit_into_playがフェアのみという保証は示していない。[Savant CSV文書](https://baseballsavant.mlb.com/csv-docs) ファウル地域でも捕球は起こる。[MLB規則用語](https://www.mlb.com/glossary/rules/foul-ball)

**従来の「通常スイングのみ」「fair_in_play＝物理的フェア」という説明を訂正する。** Phase 2aの公表数値は、固定した5description母集団の予測結果として残す。今回その値を再学習・再計算したものではない。バントを除いた改善幅や、純粋な三振回避技能を測れたとの主張はしない。

## 3. 記録と現象の接続条件

将来のゲームではD022–D023を守り、投球・判断・接触・打球・捕球等の出来事から記録を作る。物理的にファウル側へ飛んだ球でも捕球されればアウトになり得るため、記録上の `foul / foul_tip / hit_into_play` を、そのまま守備より前の物理的分岐へ置換できない。

```text
ゲームの既存方針: 投球 → 判断 → 接触 → 打球 → 捕球・走塁 → 記録
観測研究での記述: 投球条件等 → 記録されたdescriptionの予測
```

後者の条件付き予測自体は研究可能だが、守備や捕手等の影響を含み得る。予測タグを先に引き、その結果に合わせて打球・捕球・能力を後付けする方式は今回採用しない。巧打力・パワーや三振回避の較正を、記録タグの分類性能だけで承認しない。

## 4. 代替案と推奨理由

| 案 | 利点 | 欠点・判断 |
|---|---|---|
| A: 分類監査を先に行い、次のターゲットを別承認 | 誤ったフェア保証とバント除外保証を広げず、後の打球研究へ接続できる | 予測モデルの追加が1工程遅れる。今回の推奨 |
| B: 直ちに記録3分類の条件付き予測を追加 | 記録の頻度・予測性能を小さく比較できる | ゲームの物理分岐とは別物。通常スイング抽出の問題も残り、今回は保留 |
| C: sac_buntイベントだけを除いて通常スイングと呼ぶ | 実装が簡単 | バント安打・失敗等を網羅する保証がないため不採用 |
| D: 旧タグを改名し旧結果を作り直す | 名称の誤読を減らす | 旧版との追跡・再現を損なう。注記と別版で扱い、旧出力は保持 |

Aでも3 chunkの監査だけで全年度の分類問題は解決しない。既存データが、将来の物理ターゲットを識別するのに不足するとの結論も有効な成果とする。検出数ゼロを、問題がない証拠にしない。

## 5. workerへ委任する範囲（承認・設計マージ後）

研究側に専用の監査モジュール・テスト・`reports/phase2b/label-audit/` を追加する。CLIは明示入力を受ける監査だけとし、fit/evaluateやゲームへの推論APIは追加しない。

1. **入力同一性**: 既存の明示processed rootとraw rootから、D6 inventoryで指定済みのprocessed 3ファイル・各年1つのraw chunk、対応metadata/manifestだけを読む。D6のhash・実質的metadata内容を照合し、実ファイルの生バイトhashも記録する。全145 chunkの探索・自動取得・前処理の再実行は範囲外。
2. **年度全体の記録集計**: processedの既存適格行でdescription別・旧contactタグ別の分母を報告。`hit_into_play`内の記録イベント `sac_bunt*` の件数、events欠損数も別集計する。これは記録イベントで確認できる範囲に限り、全バント数と呼ばない。2025は既閲覧年度の記述監査とし、学習・選択は行わない。
3. **限定raw照合**: 3キーの欠損・重複、raw→processedの対応／非対応、対応行のdescription/events値一致、適格／非対象の分母を確認する。対象行の値不一致や重複は停止。非対応行を黙って捨てず件数と理由の確認範囲を残す。
4. **診断フラグ**: `events`のsac_bunt接頭辞、`des`の大小文字を区別しない文字列foul territory一致を、元ラベルと分けた監査注釈として集計。欠損は欠損として数える。非一致を「バントではない」「必ずフェア」と変換しない。記録以外の真値は推測しない。
5. **後続研究の入力点検**: 選定raw 3 chunkでdescription別のEV/LAの有限値・片側欠損・両側欠損を集計する。単位・出典を記録し、欠損を0で補完しない。選択された標本の観測率であり、全接触に打球測定がある、あるいは欠損が無作為とは主張しない。新たなEV/LA生成は行わない。
6. **訂正文書**: 研究REPORT等には、旧表・旧出力を残して解釈の訂正と新監査へのリンクを追記。ゲーム側のPhase 2a説明にも同じ注記を同期する。タグを将来改名・再分類する場合は別契約・版・出力・承認とする。

今回の目的はデータ監査。結果列events/des/EV/LAは監査に使用可能だが、投球条件の予測特徴やスイング判断への入力へ流用しない。新しい能力係数・バント技能・捕手補正を追加しない。

## 6. 成果物と受け入れ基準

- `plan.json`: 設計版、指定入力、診断規則、集計範囲、ライブラリ・実装識別。個人パスは公開版から除く。
- `audit.json`: 年度の5description集計、記録バント件数、各限定rawの対応・診断・EV/LA欠損集計、定義不能な項目の理由。個票・自由記述・選手ID一覧は保存しない。
- `REPORT.md`: 発見、未確認範囲、旧研究の訂正、将来のターゲット候補を分ける。ゼロ検出や低欠損を、分類の完全性・認知能力・製品採用の証明にしない。
- 新規出力先だけを許可し、入力・旧成果物を上書きしない。同じ入力・版の再実行で、実行時間等を除く数値と設定を一致させる。公開成果物のhashを付ける。
- 人工反例で、hit_into_playの犠牲バント／ファウル捕球が旧v1では接触1のまま、診断注釈だけに現れることをテストする。
- 欠損・曖昧な記録を通常スイング／フェアへ強制分類しないこと、キー重複・値不一致・入力改変の拒否、分母と重複の整合、旧ラベル非変更、出力への個票混入防止を確認する。
- 学習・推論を呼ばず、旧M0/M1/M2・Phase 1b/1c/1d/2aのコード、機械可読結果、凍結契約が不変であることを確認する。必要な既存回帰テストを実行する。
- 責任者が差分・入力hash・集計を独立に検算し、問題はworkerへ直接修正依頼する。受入れは監査実装の合格であり、分類の完全性の合格ではない。
