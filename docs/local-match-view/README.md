# PCブラウザで1試合を操作する

ゲームrepoのrootで起動する。Python3.11/3.12の標準ライブラリだけを使い、追加インストールは不要。

```powershell
python -m prototypes.match_view
```

ターミナルへ表示される`http://127.0.0.1:...`を自分でブラウザに開く。空きportを使うため、起動のたびにURLが変わる。ブラウザは自動起動しない。停止はターミナルでCtrl+C。

開発・検証時も、ユーザーの「PCを操作しない」指示を優先する。担当エージェントはユーザーの可視ブラウザ・マウス/キー・既存プロファイルを操作せず、表示検証が必要な場合は画面なしの専用ヘッドレス環境で行う。

- **1球**：既存エンジンを1球進める。
- **1打席**：次の打席完了、または試合の停止まで進める。
- **最後まで**：同じ1球処理を試合が停止するまで繰り返す。
- **新しい試合**：指定seedで初めからやり直す。seedは0〜18446744073709551615の整数で、初期値は42。

進行はメモリ上の1試合だけ。画面を再読込みすると同じプロセスの現在状態を表示する。新しい試合またはプロセス終了で以前の試合は失われ、セーブ/復帰は行わない。通信中は新しい試合を含め全操作を無効にする。複数タブも同じ1試合を共有するので、操作には1つのタブを使う。

現在打つ打者、回表裏、B/S/O、塁占有、得点表と直近の投球/完了打席を表示する。半回をまたいでも打順を持ち越す。表の`—`は未実施、0は実施した無得点。試合終了/未完了時は塁とカウントを隠し、確定したscore/lineと日本語の理由を表示する。サヨナラ時の旧snapshotは解決直前の投影であり、終端後の塁/カウントとして表示しない。

seed42を「最後まで」で進めると仮Away4–2仮Home、259球で9回裏終了。手動/1打席/最後まで/混在は同じseedのGameResultとevents_documentに一致する。

## 範囲

[設計PR #37](https://github.com/thrsth45h/baseball-sim/pull/37)・[ローカル操作画面設計](../LOCAL_MATCH_VIEW_DESIGN.md)に基づく薄い試作。既存Phase 4fのGameSessionを直接使い、野球遷移・仮重み・乱数を画面で再実装しない。全員共通toy-v1と一定進塁の未較正な仮設定を継承する。

ローカルPC向けの使い勝手を確かめる工程で、D048はPROVISIONAL。Android製品UI/言語/DBの採用ではない。公式個人成績/能力1〜20/上流知覚・接触・打球物理/研究モデル接続・12球団ペナント/球団経営は含めず、D029–D032はOPEN。実ブラウザ表示・狭幅・キーボード操作の確認状況は[検証記録](VALIDATION.md)に区別している。

## ローカルHTTP

127.0.0.1のみにbindする1プロセス・逐次HTTPServer。外部配信/トンネル/ホスティング用途ではない。許可GETは`/`、`/style.css`、`/app.js`、`/api/state`だけで、GETは試合状態/乱数を変えない。変更は`/api/command`へのJSON POSTだけ。起動ごとのtoken headerと実際のHost/Originを照合し、JSONは4,096bytes上限・正確なkeys/値を検査する。任意pathのファイル読取り/書込みAPIはない。

seedはブラウザとサーバの間でも十進文字列として扱い、JS Numberの丸めを通さない。画面用tokenは起動時HTMLで供給し、URL/ログへ出さない。外部フォント/画像/CDNは使わない。これらはローカル検証の境界であり、製品用サーバや多人数向けの認証/セッション管理ではない。
