# 1試合の操作画面（ローカル試作）

2026-10-31。基準main `d1d0ca6510177fd708c54035ee78e7f8107580b4`。Phase 4fの表示・操作を確かめる交換可能な試作。Android製品UI/技術構成の決定ではない。

## 目的・進行根拠

1コマンドで起動し、PCブラウザで合成の1試合を操作する。ユーザーの「次へ」、従来の都度確認省略指示を踏まえ責任者が選んだ次の試作であり、本人が新しい製品仕様を個別承認したと記録しない。D048はPROVISIONAL。既存D047/4fを使う薄い操作層として実装・レビュー・PR・継続許可による統合まで進める。D029–D032はOPEN。

## 選択・代替案

静的REPORTだけでは途中操作を確認できない。Androidを直ちに選ぶとD032の大きな判断を伴う。今回は標準ライブラリのPython HTTPサーバとHTML/CSS/JavaScriptでローカル画面を作り、インストール依存を追加せず既存GameSessionを直接使う。製品用サーバにはしない。

## 契約

- `python -m prototypes.match_view`で127.0.0.1のみへbindし、空きportのURLを表示。ブラウザを勝手に起動せずCtrl+Cで終了。外部配信/トンネル/ホスティングなし。
- 1プロセスで1試合をメモリ保持。seed初期値42、正確な整数0以上2^64未満。新しい試合はseed指定でGameSessionを作り直す。既定上限10,000球を維持。
- 操作は「1球」「1打席」「最後まで」。全て同じGameSession.advance_one_pitchを呼ぶ。1打席は完了打席数が増えるか停止するまで。終了後の進行は拒否し、状態/乱数を変えない。
- UI/サーバは野球遷移・乱数・仮重みを再実装しない。既存prototypes/phase4a–f、研究、既存reports/fixtures/CIを変更しない。
- 得点、1–9回得点表（未実施は—）、受理球数、回表裏、打者、B/S/O、塁占有、直近投球/完了打席を表示。実行前に今から打つ打者を正しく表示する。
- 最後まで進める操作も同一の逐球処理。手動・打席・自動・混在の最終GameResultとevents_documentが同seedで一致する。
- 終了時は勝敗/試作用引分/未完了と理由を日本語表示。サヨナラの旧snapshotは終端プレー直前なので、終了後の塁・カウントを表示しない。最終score/lineはsnapshotの確定値を使う。
- 試作・仮確率であることを画面に短く表示。公式打率/能力/EV/LA等の未実装指標を捏造しない。球団名や選手は既存の仮名を使う。
- スマートフォン幅でも横はみ出し/ボタン重複なく操作可能。意味のあるbutton/table/label、キーボード操作、状態通知。外部フォント/画像/CDN不要。
- HTTPのGETは読み取りのみ。変更はJSON POST、起動ごとの秘密tokenをヘッダで照合し、Host/Originを実際のloopback originに限定。任意path配信やファイル読取り/書込みAPIを作らない。JSONサイズ上限、値/command検証、逐次処理で競合を防ぐ。tokenをログ/URLに出さない。
- ファイル出力/セーブ・復帰/公式記録/交代/新ルール/能力/実データ/Android/12球団/経営は含めない。
