## 1. ユーザーへ提示する採用範囲

**Phase 2の最初の実装を、通常スイングにおける接触／空振りの条件付き予測に限定する。** ファウル・ファウルチップ・インプレーは別タグとして保持し、その先の分岐モデルはPhase 2bの別設計とする。

取得済み2023〜2025年データで新しい接触予測モデルを学習・評価する。これはPhase 1dの合成研究とは異なる実データ学習である。選球眼の認知的識別、公開能力1〜20の較正、ゲーム本体への組み込みは今回の承認範囲に含めない。

目的は、(1)ラベルを一貫して作れるか、(2)投球条件による接触予測がどこまでできるか、(3)打者ごとの残差を加える予測上の利点と限界を測ること。既存M0/M1/M2、Phase 1b/1c/1dとD6監査のコード・結果・推論契約を保存する。

## 2. 推奨理由・代替案

Phase 1dとD6は完了したが、公開入力から主観的知覚を立証できず、MLB向け潜在知覚・周辺確率の契約も未整備。これを能力推定で穴埋めせず、ロードマップの次の物理的な段階を独立して調べる。

| 案 | 利点 | 今回の判断と留保 |
|---|---|---|
| 接触の二値予測＋結果タグ | 小さく検証でき、後続の分岐へ接続できる | 推奨。これだけで三振回避能力や試合全体は完成しない |
| 初回から空振り・通常ファウル・ファウルチップ・インプレーの4クラスを予測 | 1球の結果に近い | 希少ラベル・分岐の較正と接触自体の問題が増える。2bで別に検討 |
| すぐ打席シミュレーションを作る | 球数・K%・BB%が見える | 配球・見逃し判定・スイング選択等の未完成モデルを混ぜる。今回は対象外 |
| 選球眼の潜在パラメータをMLBへ自由適合 | 行動予測の適合値は得られる可能性 | 認知的識別が解決しない。Phase 2aへ混ぜない |

## 3. 対象母集団・ラベル

対象は、D6で同一性を確認した各年度の処理済み `pitches.parquet` に含まれる通常スイング。既存の位置・球速等の適格性で選ばれた母集団であり、全MLB投球・全スイングを代表すると主張しない。

Phase 2a専用の `contact-label-v1` を作る。ラベル生成はdescriptionだけを使い、以下を固定する。

| description | y_contact | outcome_tag |
|---|---:|---|
| swinging_strike | 0 | whiff |
| swinging_strike_blocked | 0 | whiff |
| foul | 1 | ordinary_foul |
| foul_tip | 1 | foul_tip |
| hit_into_play | 1 | fair_in_play |

捕球されたファウルチップは接触していても、2ストライク後なら三振となる。[MLB規則用語](https://www.mlb.com/glossary/rules/foul-tip) このため接触率を三振回避能力と同一視せず、通常ファウルと別タグを保つ。タグを保持するが、この工程ではカウント遷移を実装しない。

- 見逃し、バント、ピッチアウト、自動判定等を通常スイングへ入れない。未知・欠損descriptionは理由付き隔離とし、接触0へ置換しない。
- 既存y_swingを変更しない。上表の行はy_swing=1であることを検査し、不一致なら入力整合性エラーとして停止する。見逃し等はy_contact=nullで分母から除く。
- 年度別に元の適格行数、対象スイング数、非対象数、未知・不一致件数、5つのdescription件数、4タグ件数を保存する。対象数＝whiff＋ordinary_foul＋foul_tip＋fair_in_playを確認する。
- `type`、打席終了の`events`、EV/LA、ヒット結果、得点、既存K/BB等からラベルを推測しない。

## 4. 予測対象と情報境界

```text
P(contact=1 | 実際に通常スイングした, 観測投球条件X, 学習済み打者の残差)
```

これは観測されたスイングの条件付き予測で、全ての球に振らせる介入の成功率ではない。スイング選択、配球、対戦相手、戦略等の影響が残る。推定した打者残差を運動技能・三振回避の真値とは呼ばない。

Phase 1のスイング確率による逆確率重み付け等で、見送った球の未観測の接触結果を復元したとは扱わない。今回はその因果推定や追加仮定を導入しない。

最終位置・実球速・確定球種を用いるオフライン予測である。Phase 1dの打者の判断器へ真値を渡す変更ではない。将来のゲームでスイング判断と接触計算を結合する方法は別承認とする。

| 情報 | Phase 2aでの扱い |
|---|---|
| plate_x/z、sz_top/bot、release_speed、pitch_type、stand、p_throws、balls、strikes | 予測の条件。2023〜2025年の座標契約に限る |
| batter | 2023年だけで作った残差のキー。未知・小標本は残差0 |
| game_pk、投球キー、game_date/year | 分割・重複検査・試合クラスタ集計。モデル特徴にはしない |
| description、y_swing、y_contact、outcome_tag | 対象選定・ラベル・評価専用。推論器の特徴にしない |
| type、events、打球・走者・得点・将来情報 | 推論特徴にしない。新たな履歴モデルは作らない |

## 5. 最小の比較モデル

既存スイングモデルと名前・出力を分離してC0/C1/C2とする。公開能力やゲーム用パラメータではない。

| 候補 | 固定する構造 |
|---|---|
| C0 | 2023年の対象スイングの接触率を定数として返す。p=(接触数+0.5)/(対象数+1) |
| C1 | 共通投球条件のridge logistic。切片は罰せず、その他の係数のpenaltyは1.0 |
| C2 | C1のlogitを固定したoffsetとし、2023年の対象スイングが50球以上の打者だけ接触残差bを追加。p=logistic(logit_C1(X)+b) |

C1は変更しない既存FeatureEncoderのfull=Trueの投球条件基底を使用可能とする。位置の多項式・共通の幾何q・zone・球種別球速標準化・12カウント・4左右・球種ダミーを2023年の対象スイングだけで学習する。幾何qは共通の位置基底に限り、打者別q相互作用dは追加しない。FeatureEncoderは結果列を使わないことをテストし、依存ソースを実装識別へ含める。

C2ではC1の係数・変換を再推定しない。打者別に次を最小化する。

```text
sum_i [log(1+exp(eta_i+b)) - y_i*(eta_i+b)] + lambda*b^2/2
eta_i = C1の固定logit
lambda候補 = {10,50,200}
```

- lambda>0で二階微分はsum p_i(1-p_i)+lambda>0。既知打者の残差解は一意。
- 未知打者、2023年の対象スイング50球未満、キーなしはb=0とし、**C1と同じ確率を返す**。2024/2025を見て対象者や閾値を変更しない。
- 2024年のLog LossでC2のlambdaを選ぶ。最小値+1e-10以内の候補から大きいlambdaを選ぶ。C0/C1/選択C2の研究上の候補選択も2024年だけで行い、最小値+1e-10以内ならC0→C1→C2の順とする。
- 50球、penalty、候補範囲、平滑化、同等差は研究プロトコルの仮設定。能力の実測係数ではない。結果を見た拡張・変更は別計画とする。
- 学習目的は投球ごとの二項負対数尤度の合計。C1はL-BFGS-B、ゼロ初期値、maxiter=1500、ftol=1e-10、gtol=1e-6。success・有限値・最大勾配絶対値/n≤1e-5を確認する。C2は単調な勾配のrootをBrent法で求め、区間[-max(1,n/lambda),+max(1,n/lambda)]、xtol/rtol=1e-12、maxiter=100とする。未収束を成功扱いしない。

2023の対象が空または二値の一方がない場合、2024の対象が空の場合は停止する。事前固定した候補の一つでも未収束ならfitは未完了とし、成功した候補だけを残して選択しない。

## 6. 分割・凍結・評価

1. **2023学習**: 対象ラベル、変換・カテゴリ・球速統計、C0/C1/C2の係数と打者対象者を決める。
2. **2024開発**: 事前固定した候補からlambdaと研究上の予測候補を選ぶ。追加の特徴や再較正をここで自動探索しない。
3. **凍結**: 設計版、全設定、2023/2024入力・実装・依存版・変換・全候補と選択結果を保存する。
4. **2025再現比較**: 凍結したC0/C1/C2を同じ対象投球で評価する。**2025は既閲覧年度であり、新しい未使用holdout・前向き検証と称しない。** 2025で候補や係数を変更しない。

学習処理は2025年の実ファイル・metadataを読み込まない。評価時は凍結済みの2023/2024入力識別と現在の入力を照合し、2025の同一性・年度・キーを別に検査する。Phase 1b/D6に提出されたファイルhashとの対応を記録する。

### 主比較と指標

主比較は2025年の **ΔLog Loss=C2−C1（負ほどC2が良い）**。C2は2024年で選んだlambdaの1候補に固定する。研究上C0/C1が選ばれても、凍結したC2との主比較を省かない。

- C0/C1/C2のLog Loss、Brier、AUC、観測・予測接触率、10等幅ビンの校正とECEを保存する。損失計算だけpを[1e-15,1−1e-15]へclipし、その事実を記す。
- 年度、12カウント、左右、球種、既知50球以上／既知50球未満／未知打者、4タグ別の分母と点推定を保存する。タグ別の単一クラスAUC等、定義不能な値はnull・理由付き。
- タグ別は結果に条件付けた記述であり、タグ間の校正・技能差を推定する比較ではない。
- 分類境界の補助記述として、固定モデルのままfoul_tip除外／swinging_strike_blocked除外の指標を別々に保存する。別母集団の記述であり、再学習・頑健性の追加証明とは呼ばない。
- 主比較の95%区間だけを、2025のgame_pkによる対応付き500回percentile bootstrapで求める。同じ試合の全対象スイングを一緒に復元抽出し、損失差の合計/球数で集計する。学習固定・選択固定で、再推定の不確実性は含めない。
- game_pkを昇順に固定し、NumPy Generator(PCG64(20261028))をbootstrap専用に一度生成。各反復でG試合からG個のindexをintegersで抽出。linear補間の0.025/0.975分位を使う。G<2や無効反復があれば区間null・理由付き、成功反復の選択・再抽選をしない。
- 既閲覧年度内の条件付き予測比較である。区間が負でも、認知能力・因果効果・ゲームへの採用を証明しない。実用上の最小改善幅と能力換算はD029のOPENを維持する。

## 7. 実装・入力・成果物の境界

ユーザー承認・設計マージ後、責任者が研究側の専用worktreeとブランチを用意してworkerへ割り当てる。workerは作業前にブランチ・HEAD・未保存変更と、importされるパッケージが自分の作業領域にあることを確認する。

新規 `baseball_calibration.phase2a` と専用テスト・新しい出力を追加する。旧ラベル・モデル・CLI・依存設定・出力を上書きしない。再利用する共通関数は変更せず、その依存ソースも識別する。現行依存版のまま実装できない場合は責任者へ戻す。

計画するCLIは次の3段階。名前の細部はworkerが同じ意味のまま実装してよい。

```text
python -m baseball_calibration.phase2a smoke --output <new-directory>
python -m baseball_calibration.phase2a fit --data <explicit-processed-root> --output <new-fit-directory>
python -m baseball_calibration.phase2a evaluate --data <same-root> --study <frozen-fit-directory> --output <new-evaluation-directory>
```

- 入力は取得済みの処理済み2023/2024/2025と対応metadata。元ファイルは読み取り専用。自動探索・新規取得・raw全件再処理をしない。
- 年度・R試合・重複キー・対象ラベル整合・有限な入力・年度間のgame_pk重複を検査し、既存の入力hashを照合する。入力不一致をmetadataの書換えで正当化しない。位置を補完しない。未知球種は2023年の共通球速統計とゼロ球種ダミーを使う。
- smokeは合成データだけの工程検査。設定・seed・人工ラベル生成を記録し、MLBの結果として扱わない。smokeを実データ学習やモデル選択の結果キャッシュにしない。
- 既存出力先は常に拒否し、ファイルキャッシュからの途中再開は実装しない。同じ入力・実装で新しい出力先へ再実行する。
- plan、manifest、ラベル監査、候補・凍結モデル、評価、REPORTを保存。数値ペイロードと日時・時間・RSSを分ける。新規JSONはcanonical UTF-8/LFのバイト列で保存・hash照合し、元のParquetや既存成果物の改行は変えない。実装識別はUTF-8ソースをLFに正規化する規約を明示し、入力ファイルhashは生バイトに対するものとする。
- 実選手IDを含む係数・対象投球・詳細モデルはGit除外のローカル出力へ置く。Gitへ出すのは小さな集計、設定、hash、安全な人工参照ケースとREPORT。生投球行・選手別値・個人フォルダ絶対パスを入れない。
- 実データ学習の成果物はsource_kind=real、trained_on_real_data=trueを明記する。ability_calibrated=false、cognitive_identification=not_established、product_adoption=falseを分ける。予測学習と能力較正・認知検証を同じ状態にしない。smokeはsynthetic/falseとする。

## 8. 資源・完了条件

全年度を一度に全列結合せず、対象列を年度ごとに読む。OPENBLAS_NUM_THREADS=1、OMP_NUM_THREADS=1と依存版を記録する。smokeで時間・最大RSSを測定し、実ファイルmetadata・対象列のサイズも確認して全量の処理方針を記録する。

fit/evaluateそれぞれ30分・最大RSS 2GiBを今回の研究資源管理値とする。超過見込みなら実行前に最適化・分割を検討し、実行中の超過はresource_limitとして未完了を報告する。年度・ラベル・候補を黙って削って成功にしない。Androidの要件ではない。

| ID | 工学的な完成条件 |
|---|---|
| P2-G1 | 5descriptionの二値ラベル・4タグ、非対象/未知の扱いと分母整合が正しい。旧y_swingを保存 |
| P2-G2 | 結果・将来列の変更が予測を変えない。fitの2025アクセスを例外で検出。変換・対象者は2023だけで決まる |
| P2-G3 | C1固定offset、C2の有限・一意な解、未知/小標本のC1完全フォールバックと残差単調性を検査 |
| P2-G4 | 同一2024集合で候補を選択して凍結。2025で再選択しない。不利な結果と未収束を隠さない |
| P2-G5 | 損失・分母・空群null・対応付き試合bootstrap・固定500反復・quantile規約を独立した小例で照合 |
| P2-G6 | 1球の参照推論とbatchが1e-12以内、再実行の数値ペイロード一致。版と入力不一致・既存出力を拒否 |
| P2-G7 | 合成smokeと実データfit/evaluateを区別し、実測資源・未実施・限界・全候補を報告 |
| P2-G8 | 既存テストと新しい意味のある契約テストが成功。基準mainの既存追跡ファイルの内容は不変 |

肯定的なΔLog Loss、能力推定、K%/BB%の一致は完成条件にしない。研究実行の完了、予測上の結果、認知妥当性、能力較正、製品採用を分けて報告する。
