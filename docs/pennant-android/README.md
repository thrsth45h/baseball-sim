# Android最小ペナント（Phase 5a）

[承認済み設計](../PENNANT_BASIC_DESIGN.md)・[保存層](../pennant-store/README.md)をAndroidへ接続する技術検証版。[PR #44](https://github.com/thrsth45h/baseball-sim/pull/44)。初回受入れは単年度で、製品の年数上限や永久の保存互換を定めない。現時点では最終CIの検証中であり、未検証を完成済みと報告しない。[検証記録](VALIDATION.md)を参照。

## 操作

1. 起動後、上部の「ペナント」を開く。「1試合」は以前の単独試合モード。
2. 開始値（seed、0〜18446744073709551615）と注目球団を選び、「新シーズン」を押す。既存進行データの置換は確認画面を挟む。手動セーブは残す。
3. 「次の自球団試合を開く」で前の未消化試合を進め、注目球団の試合を開く。「1球」「1打席」「最後まで」で進める。
4. 「1日進める」「シーズン終了まで」は同じ試合エンジンを画面なしで反復する。「停止予約」は進行中の1試合が終わると停止する。
5. 「日程」で過去/未来の140日、「順位」でリーグ別6球団、「記録」で12球団の固定9人ずつを見る。横長の表は横へスクロールできる。
6. 試合外では「セーブ」で1件の手動slotを保存し、「ロード」でその時点へ戻る。試合中は手動操作が無効になる。公開する操作結果は先に端末へ自動保存する。

月曜は休養日、1球団120試合、全720試合。固定の仮設定で、能力差・正式な打率/打点/投手記録・采配・経営・次年度移行は今回含めない。セーフ安打イベント数は本塁打を含む。

## 終了・エラー・再起動

画面再生成で投球し直さない。プロセスが終了した場合は「ペナント」を開くと、最後の保存済み操作から同じsnapshot/RNG/source消費を再生照合して復旧する。試合中にアプリを閉じても手動ロード可能な試合外へ変換しない。

未完了エラーは試合IDと保存理由を表示して停止する。進行/手動save/loadで再抽選せず、確認付きの新しい検証シーズン開始のみ可能。保存データを読めない場合は元データを残し、勝手に新規作成しない。「保存を読み直す」で再確認する。

今回保証を検証するのはアプリのプロセス終了。突然の電源断、媒体故障、実機一般性能、将来の製品セーブ互換は別の対象。

## APKとCI成果物

最終の検証済みAPK取得先・source head・SHA256・14日保持期限は、検証完了後に[検証記録](VALIDATION.md)へ固定する。CIの`pennant-debug-<source SHA>` ZIPに`app-debug.apk`、hash、`source-info.json`、Room/KSP/schemaを含む`pennant-source-info.json`、process復旧の検証結果を同梱する。

debug署名はCI runnerごとに異なる場合があり、versionCodeが増えても以前のdebug APKから保存を保った更新を保証しない。同一applicationIdで署名が違うと更新できず、アンインストールすると端末内セーブも消える。こちらから端末へ自動インストール/アンインストールはしない。固定の製品署名やPlay配信は今回の範囲外。

## 検証の分け方

- 日程/単独試合の互換、3master計2,160試合と集計は[純Kotlinの検証](../pennant-core/VALIDATION.md)。
- SQLiteトランザクション/障害注入/slot/世代は[保存層](../pennant-store/README.md)。
- 本PRはVMの連打/世代/読込失敗、実Activityの操作/720実transaction、狭幅/診断表示、hostによる実force-stopを検査する。APKビルド成功と動作成功は区別する。

ビルド・エミュレータは隔離CI内。ユーザーPCの画面/入力/既存プロファイルを操作せず、SDK/JDK/Gradle/IDEもローカルへ導入しない。
