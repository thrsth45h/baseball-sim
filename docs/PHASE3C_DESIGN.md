## 1. 相談する最小範囲

**固定した人工条件から、打球がどこへ何秒で地面に届くかを計算し、守備者1人の移動距離の余裕を求める。** 打球の初期条件→軌道→最初の地面到達→守備側の距離予算、という順序を動かす研究用プロトタイプを提案する。

今回は空気抵抗・風・回転のない仮想空間と、平面上を反応時間後に一定の最大速度で移動できる点状の守備者を使う。出力は軌道、地面到達時刻と位置、移動距離予算と差、および差の符号の分類まで。**飛行中の捕球、捕球成功確率、公式のアウト/安打、フェア/ファウル判定は生成しない。**

Phase 3bの限定記録集合の生成器やMLBデータは接続しない。新規取得・rawの追加監査・学習・能力1〜20・複数守備者・球場/フェンス・地面反発/転がり・走塁・得点・ゲーム本体への統合も含めない。旧研究のコード・結果・契約・凍結索引を保存する。

## 2. この順序を選ぶ理由・代替案

Phase 3bで具体的なEV/LAを返せるようになったが、対象は数値のあるhit_into_play記録に条件付けられている。全接触の守備前分布ではない。方向や実際の守備を加えるには、その入力が何を観測したものかも確認する必要がある。

Savant CSVのhc_x/yの説明からは、原点・尺度・記録時点・初期方位との対応を確認できない。hit_locationは最初に接触した守備位置の記録である。[公式CSV文書](https://baseballsavant.mlb.com/csv-docs) pybaseball 2.2.7のspray角はhc座標の変換で、図上原点や0.75の補正を含む。独立した初期方位の測定とは扱わない。[ツール実装](https://github.com/jldbc/pybaseball/blob/2.2.7/pybaseball/datahelpers/statcast_utils.py)

| 案 | 利点・制約と今回の判断 |
|---|---|
| A: 座標等の全量欠損監査を先に追加 | 記録の到達率は分かるが、欠損率だけでは初期方位や時間の意味は決まらない。列の意味の契約表だけ先に置き、追加監査は用途決定後とする |
| B: hcからの図上方向とEV/LAの予測研究 | 記録図を再現する研究として可能。守備前の方向を識別したことにはならず、今回は保留 |
| C: 合成条件で軌道と距離予算を動かす | 単位・座標・時刻・処理順を具体化できる。実測精度の検証とは分けて進める。推奨 |
| D: 直ちに飛球捕球・地面反発・公式記録まで実装 | 進行に近づくが、複数の未較正仮定と規則を同時に導入する。今回は保留 |

MLBの外野捕球指標は距離・機会時間等を使うが、本案はその再実装ではない。[Catch Probability](https://www.mlb.com/glossary/statcast/catch-probability) 合成例で数式どおり動いても、MLBの飛距離や守備成功率に妥当なモデルになったとは認定しない。

## 3. 観測記録と生成入力の契約

以下は出典と用途の区別。ここで新たに145ファイルの座標値・欠損率を監査したという意味ではない。

| 候補記録 | 確認できること・未確認事項 | 今回の扱い |
|---|---|---|
| launch_speed / launch_angle | 記録EV/LA。一部推定を含み、対象選択がある | 旧3bを保存し、新プロトタイプへ読込まない |
| hc_x / hc_y | 記録上の打球座標。初期方位や最初の地面到達点との対応は未確認 | 方位・距離・初期状態へ自動変換しない |
| hit_distance / rawで使われるhit_distance_sc | 公式の説明はprojected hit distance。列名対応・単位や初回地面到達距離との同一性は別確認が必要 | 地面到達距離・飛行時間の正解値にしない |
| hit_location / events / description | 接触した守備位置やプレー/投球の結果記録 | 初期条件や守備者位置を逆算する入力にしない |
| fielder_2…9 | 参加守備者ID。個人の開始XY座標ではない | 座標に代用しない。IDも新コードへ読込まない |
| if_fielding_alignment / of_fielding_alignment | 配置の分類であり、個々の連続XY位置と同一とは確認できない | 人工の開始位置と区別する |
| vx0/vy0/vz0・ax/ay/az | 投球の軌道係数 | 打球の初速や加速度に流用しない |

前表のCSV定義は[公式文書](https://baseballsavant.mlb.com/csv-docs)を基準とする。不明な意味・観測時点は未確認のまま保持する。Phase 3cの人工入力は、これらと別の型・schemaで表現する。

## 4. 人工入力・単位・支持範囲

原点は仮想ホームプレートの地面。捕手から外野を見る向きで右を+X、中堅方向を+Y、鉛直上を+Zとする。初期位置は(0,0,h)。方位θは中堅方向0度、右方向+90度。高さ角φは水平0度、上向き正。

| 入力 | 範囲 | 単位 |
|---|---|---|
| ev_mph | 0以上200以下 | mph |
| la_deg | −90以上90以下 | 度 |
| azimuth_deg | −180以上180未満 | 度 |
| height_m | 0超5以下 | m |
| 守備者initial_x_m / initial_y_m | 各−1000以上1000以下 | m |
| reaction_s | 0以上30以下 | s |
| move_speed_mps | 0以上20以下 | m/s |

これは**合成計算の検証範囲**で、実際の打球/人体の上限・リーグ分布・能力尺度ではない。全数値は有限で、bool・数値文字列・NaN/Infinity・範囲外は拒否する。計算結果を有限に表現できない、または地面到達時刻T>0を表現できない入力もエラーとする。clip・補完・再抽選で継続しない。

1mph=0.44704m/sを使う。[NIST換算表](https://www.nist.gov/pml/special-publication-811/nist-guide-si-appendix-b-conversion-factors/nist-guide-si-appendix-b8) g=9.80665m/s²を固定する。[標準重力の値](https://physics.nist.gov/cuu/pdf/adopted_2002.pdf) 球場ごとの重力測定ではない。重力だけの運動方程式を用いる。[運動方程式](https://openstax.org/books/university-physics-volume-1/pages/4-3-projectile-motion)

## 5. 軌道・最初の地面到達

V=0.44704×ev_mph、角度は三角関数の前にラジアンへ変換する。

```text
vx = V cos(phi) sin(theta)
vy = V cos(phi) cos(theta)
vz = V sin(phi)
x(t) = vx t
y(t) = vy t
z(t) = h + vz t - g t²/2
S = sqrt(vz² + 2 g h)
vz >= 0: T = (vz + S) / g
vz <  0: T = 2 h / (S - vz)
ground = (vx T, vy T, 0)
```

h>0なのでTは最初の正の地面到達時刻。下降初速では正根の相殺を避ける式を使い、逐次時間積分で地面を探さない。positionは0≤t≤Tだけを扱う。終端地面イベントのzは定義上0であり、実測値の補正ではない。

正確なφ=±90度では水平初速を0とし、θ=0/±90/−180度も対応する成分の0や符号を正確に扱う。三角関数の微小残差から、静止守備者と鉛直打球の人工例に偽の水平距離を作らない。

## 6. 単一守備者の移動余裕

守備者は初期点F=(fx,fy)に静止し、反応後に速度s以下で任意の方向へ直線移動できると仮定する。加速度、身体サイズ、捕球、障害物、判断誤差、飛行途中の迎撃は扱わない。

```text
d = hypot(ground_x - fx, ground_y - fy)
available_s = max(T - reaction_s, 0)
budget_m = move_speed_mps * available_s
margin_m = budget_m - d
epsilon_m = 1e-9
margin_m >  epsilon_m: positive_margin
margin_m < -epsilon_m: negative_margin
otherwise: boundary
```

これは**真の地面到達点を既知とした、理想化した移動距離予算の差**。守備者の認知や実際の行動・捕球可能性ではない。εは固定した数値分類幅で、観測精度・捕球半径や能力ボーナスではない。NaNが比較をすり抜けてboundaryになることを禁止する。

もともと地面到達点に居れば移動不要で、速度0/反応が遅い場合のmargin=0もあり得る。boundaryはそのような等号と数値境界を示す区分で、捕球失敗という意味ではない。**negative_marginでも飛行途中なら捕球できる場合があり、positive_marginでも捕球成功は保証しない。** 両者をアウト/安打へ変換しない。

## 7. 固定する12例と検証

下表はlaunch=(EV,LA,方位,高さ)、fielder=(X,Y,速度,反応時間)。§4の単位を使う。固定例の入力をrunで先に保存し、出力から初期条件を変更しない。

| ID | launch | fielder | 点検する性質 |
|---|---|---|---|
| drop_stationary | (0,0,0,1) | (0,0,0,0) | 自由落下、距離0、boundary |
| horizontal_still | (10,0,0,1) | (0,0,0,0) | 水平打球、移動なし |
| horizontal_mobile | (10,0,0,1) | (0,0,10,0) | 速度を増やした距離予算 |
| horizontal_delayed | (10,0,0,1) | (0,0,10,1) | Tより遅い反応 |
| vertical_up | (10,90,0,1) | (1,0,0,0) | 真上、水平成分0 |
| vertical_down | (10,-90,0,1) | (0,0,0,0) | 真下、安定な正根 |
| mirror_left | (60,30,-30,1) | (-20,40,7,0.2) | 左右反転 |
| mirror_right | (60,30,30,1) | (20,40,7,0.2) | 左右反転 |
| rotate_forward | (40,20,0,1) | (-10,20,7,0.2) | 水平回転 |
| rotate_right | (40,20,90,1) | (20,10,7,0.2) | 水平回転 |
| budget_boundary | (10,0,0,1) | (0,0,4.4704,0) | 距離予算の等号 |
| domain_edges | (200,45,-180,5) | (1000,-1000,20,30) | 検証範囲の端点・後方 |

例は境界検証用で、リーグからの抽選標本ではない。分類の割合を現実の捕球率・フェア率へ解釈しない。

各例の軌道表示はt_i=T×(i/32)、i=0…32の33点。最終点は地面イベントを使う。これは表示用の標本で、Tや距離予算の判定をこの離散列から求めない。

受入れ検証は以下。正の余裕の例が多いことや、実際の捕球率に近いことを合格条件にしない。

1. 単位変換・軸と符号・入力型/範囲、0初速・上下鉛直・上下端、NaN/Infinityと表現不能の拒否。
2. 自由落下・水平・鉛直の手計算/高精度の別式と照合し、地面の正根と時刻、地点、距離予算を検証。独立参照との比較は絶対誤差1e-9（秒/m/m/s）または相対誤差1e-12以内とする。境界分類は固定εで別に検査する。
3. 左右反転と、守備者座標も変換する水平回転で、T・d・budget・marginが一致。回転後も入力範囲内の例を使う。
4. 守備者の速度↑・反応時間↓でmarginが悪化しない。守備者変更で軌道/T/地面地点が変わらない。EV↑で捕球しにくくなる等の未定義な単調性は課さない。
5. ±εの境界分類と、十分に境界から離れた正負を検査。等号・速度0・反応後に地面到達済みも確認する。飛行途中の捕球と地面到達点の移動余裕が異なる反例を保持する。
6. 同じ人工入力は単独/一括/実行順変更で同じ結果。RNGを使わず、乱数呼出しがないことも確認。旧データ/モデルのファイル・Parquet読込みは禁止し、アクセス監視で確認する。
7. 初期条件schemaはhc座標・events・安打/アウト・能力値等の未知フィールドを拒否する。これは外部の数値の来歴を自動証明する仕組みではなく、人工runnerの出所と情報境界を検証するもの。
8. 既存全439テストと新規の必要なテストを実行。旧コード・数値・凍結索引と推論契約の非変更を確認する。

## 8. 実装・公開・承認

本人承認・設計マージ後、workerへ研究側の新規`baseball_calibration.phase3c`と専用テスト、`reports/phase3c`/`data/phase3c`の新規出力を委任する。既存ファイルはroot README案内以外変更しない。既存の計測ユーティリティ等の純粋な再利用は可、旧研究モデル・データ読込みへの依存は作らない。依存版は維持する。

CLIは固定人工例だけの`python -m baseball_calibration.phase3c run --output data/phase3c/run-01`。raw-root/frozen/seed/外部入力のオプションを作らない。出力はplan.json、scenarios.json、results.json、REPORT.md、execution.json、SHA256SUMS.json。設計版、全仮定/範囲/境界、固定例、使用ソース/依存版を結合して記録する。

`source_kind=synthetic`、`trained_on_real_data=false`、`connected_to_phase3b=false`、`MLB_validity=not_established`、`ability_calibrated=false`、`product_adoption=false`を明示する。新規出力先のみ許可し、既存出力への上書き・旧namespace出力・入力との重なりを拒否する。各run30分・peak RSS2GiBを停止目安とし、結果・超過を隠さない。

異なる新出力先で2回実行し、時間/資源記録とそれを含むhashを除く4成果物のバイト一致を確認する。責任者は別worktreeでコード・全テスト・再実行・独立期待値・旧成果物保持を点検し、必要な修正はworkerへ直接依頼する。CIは対象headのPython3.11/3.12を確認する。

Phase 3bはEV尾部が無上限、本案は人工の検証範囲が200mph以下であり、そのまま接続する契約ではない。clip・範囲外だけの再抽選でつながず、将来は支持範囲と選択の扱いを別に決める。MLBとの較正・全接触・実際の守備認知/捕球・公式記録・能力・ゲーム採用は別承認。
