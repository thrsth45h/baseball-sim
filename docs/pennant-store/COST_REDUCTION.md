# 保存処理の限定的な計算量削減

Phase 5aの実720試合進行の診断に伴う通常修正。ハッシュのSHA-256 digestを32個のFormatterで文字列化する処理を、同じ小文字2桁のhex変換へ変更する。全byte・負のbyte・既知SHA-256ベクトル・固定seedのbufferを旧Formatter参照と照合するJVM試験を追加した。

commitでは既存prefixを検査した後、結果をrowへ変換する前にそのprefixを除く。markerや表示球団変更では新規rowは0、1試合完了時は1件だけ変換する。手動ロードは全結果を新世代へ登録するため、全row変換を維持する。実DB回帰は0/1件の追加後の既存row全byte保持と、書き換えたprefixの拒否を確認する。

保存形式・schema・codec・再生/破損検査の回数・transaction/CAS・callback順・世代/操作ID判定は変更せず、キャッシュも導入しない。新しい試験と旧回帰はCIで実行する。局所profileと実720試合の完走結果を回収するまで、改善率や完了時間を実測値として主張しない。これらの最終検証はAndroid接続PR #44に統合して報告する。ローカルSDK/GradleやユーザーPC画面は操作しない。
