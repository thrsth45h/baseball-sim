# ADR-0014: Android最初の1試合アプリ

- Status: **Proposed**
- 関連決定: D032 OPEN、D049 PROVISIONAL
- ユーザーの明示承認記録: **未承認**。「つぎへ」は次案の検討根拠で、言語/Android構成の本人採用とは扱わない。
- 正本: [具体案・代替案・検証条件](../ANDROID_FIRST_MATCH_DESIGN.md)

## 現状と問題

Pythonの合成試合とPCブラウザ操作はmainへ統合済み。Androidで単独動作するアプリはなく、D032は未決定。PCのHTTPサーバを前提にしたままではスマートフォン単体の試作にならない。

## 推奨と反論

Kotlin＋Compose、Android非依存core、ViewModelによる一方向の表示更新を推奨。Flutterの他OSとの共有より、現在確定しているAndroidを優先する判断案である。Pythonルール移植のコストと不一致リスクがあり、固定入力列による逐球互換を必須とする。公式推奨は完成や性能の証明ではない。

## 採用を求める範囲

単体オフラインのdebug APKまで。限定ルール・仮重みを保ち、版付きsm64-v1の乱数と3操作の同一性を検証する。最低API26を提案。DB/製品セーブ/長年ログ、能力較正/MLBモデルの採用、12球団/経営、配信は確定しない。旧研究/参照実装/結果を保持する。

## 承認後

言語/最小構成について本人の回答を正確に記録し、設計PR統合→worker実装→責任者の独立レビュー→問題解決・CI確認→継続許可の範囲で実装PR統合へ進む。承認までは実装も設計PRのマージもしない。ユーザーPCのUI/入力は操作しない。
