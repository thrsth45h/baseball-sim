# ADR-0014: Android最初の1試合アプリ

- Status: **Accepted**（2026-11-01）
- 関連決定: D032の言語/初版構成とD049 CONFIRMED、D056 OPEN
- ユーザーの明示承認記録: **2026-11-01正式承認**。「設計PR #39の Kotlin＋Jetpack Compose構成を承認します」。今回の限定移植/debug APK・検証・通常判断/修正/レビュー後マージを承認。長期方針は記録だけに分離する。
- 正本: [具体案・代替案・検証条件](../ANDROID_FIRST_MATCH_DESIGN.md)

## 現状と問題

Pythonの合成試合とPCブラウザ操作はmainへ統合済み。提案作成時点ではAndroidで単独動作するアプリはなく、D032は未決定だった。現在は言語/初版構成を承認済みで、保存等の具体方式はD056 OPEN。PCのHTTPサーバを前提にしたままではスマートフォン単体の試作にならない。

## 推奨と反論

Kotlin＋Compose、Android非依存core、ViewModelによる一方向の表示更新を推奨。Flutterの他OSとの共有より、現在確定しているAndroidを優先する判断案である。Pythonルール移植のコストと不一致リスクがあり、固定入力列による逐球互換を必須とする。公式推奨は完成や性能の証明ではない。

## 承認された範囲

単体オフラインのdebug APKまで。限定ルール・仮重みを保ち、版付きsm64-v1の乱数と3操作の同一性を検証する。初版の最低対応は設計に従いAPI26。DB/製品セーブ/長年ログ、能力較正/MLBモデルの採用、12球団/経営、配信は確定しない。旧研究/参照実装/結果を保持する。

## 承認後

言語/最小構成について本人の回答を正確に記録し、設計PR統合→worker実装→責任者の独立レビュー→問題解決・CI確認→継続許可の範囲で実装PR統合へ進む。本人承認を反映済み。設計レビュー後に統合し、そのmainからworker実装を開始する。sm64-v1は今回用で製品へ永久固定しない。ユーザーPCのUI/入力は操作しない。
