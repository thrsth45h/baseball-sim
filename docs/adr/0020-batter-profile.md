# ADR-0020: 未較正の打者タイプを、新しい試作世界の逐球生成に限定する案

- Status: Proposed
- 関連Issue：設計PRへ集約
- DECISIONS ID：D062 PROVISIONAL
- ユーザー承認：**未承認**。「つぎへ」は設計を進める依頼として扱う。
- 基準main：`68d44b0e87f0a7ac454db1908cb6c41705db0416`
- 正本：[打者の試作用タイプ](../BATTER_PROFILE_DESIGN.md)

## 現状と問題

PR #51で実出場者と個人記録はつながったが、生成器は全員同じで編成による分布差がない。D029の正式能力係数と研究の製品統合は未検証である。

## A案・B案・現状維持

Aは標準/ミート型/長打型の明示整数表を新規v3だけへ導入し、人物へ結び付けた試合前入力を使う。Bは投手等の接続を先行し、Cは正式モデル研究を先行する。現状維持では編成の分布差は試せない。

## 推奨理由、反証、トレードオフ

Aなら既存の1球ルールと記録・保存を再利用して選手差を試せる。ただし仮表の作り直し/保存版追加の負担があり、正式能力の開発が進んだと誤認しやすい。知覚/接触/打球/守備の生成過程を完成させず、三タイプの強さの均衡も未検証。独立した傾向や能力1〜20に読み替えない。

## 事実と仮定

事実は現行ソース/保存契約と、正本の表から責任者が有理数で導いたカウント終端確率。すべての新しい重みと三タイプの人物配置はゲーム試作用の未較正仮定で、MLB研究/実測による能力係数ではない。呼称から選球眼/積極性を推論しない。

## データ・UI・旧保存への影響

新`PitchSource`を既存coreへ注入し、人物/タイプ/版を開始前に固定する。新規v3だけへ使用し、旧v1/v2は旧sourceのまま進行・保存・復旧できる。同じRoom schema1とCAS/receiptを維持。画面は試作用タイプと既存5件数を示す。正式能力やEV/LAを捏造しない。

## 受け入れ基準

正本の8条件。境界/有理数の理論検算、人物対応、事前固定の独立参照、各進行単位と保存復旧、旧v1/v2 byte回帰、実Androidのv3全720/全144人、同配布APKの3形式host force-stop、責任者の独立レビューまでを要求する。実機/API26等は実施と未実施を分ける。

## 判断を求めること／承認後の工程

新しい仮分布差の採用なので、正本の表・範囲・限界を本人へ提示して承認を得る。D062はPROVISIONAL、D029はOPENのまま。承認前に実装/設計PRマージを行わない。承認後は台帳更新と設計統合、worker実装と責任者の独立レビュー/修正、CI/検証APKと問題のないPR統合へ進む。
