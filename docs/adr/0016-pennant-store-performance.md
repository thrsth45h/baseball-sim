# ADR-0016: ペナント保存成功応答の重複検証を減らす案

- Status: **Accepted**（2026-11-11、Phase 5aの内部改善に限定。未実測）
- 正本: [性能改善設計案](../PENNANT_PERFORMANCE_DESIGN.md)
- 対象: D057/D058の限定試作。既存承認を新しいDB/ゲーム仕様へ拡張しない。

## 現状

PR #44はmain `7ebb4a46a319ffde5e390a86b8f0a3a0352e4866`へマージ済み。実720試合に18分30.228秒を要したAPI35 debug CIの記録がある。通常commitでは候補検証・更新前read・成功後readがそれぞれ全frameを解釈する。過去の局所修正では高速化を確認できなかった。

## 提案と反証

まず区分計測し、通常commit成功後だけ、今回の検証済み候補と新鮮な原子的raw読取の全byte/全列一致を根拠に意味検証の重複を減らす。公開read/再起動/例外/重複/no-op等は厳密経路を維持する。tokenだけのキャッシュは同tokenの破損を見逃し、全frameや保存頻度の変更は互換性/復旧契約へ影響するため採らない。

正確なDB照合が重ければ効果は小さい。可変参照、receiptのfingerprint、ledger既存prefix、世代競合のどれかを見落とす実装は不合格。並行操作後の別状態を旧操作の成功にする既修正不具合を復活させない。検証済み値の再利用は操作内に限定する。

## 影響・検証・採否

schema/codec/RNG/ゲームルール/UI/保存時点は不変。正本に同token改変/障害/世代競合/可変参照の反例試験、全720最終frame一致、実force-stop復旧、ABBA局所計測と暫定性能ゲートを規定する。安全性または性能を立証できなければ計測のみで見送り、未達を隠さない。

2026-11-10の「次へ」は次工程の設計を進める依頼だった。その後[PR #45](https://github.com/thrsth45h/baseball-sim/pull/45)と「試合結果/乱数/保存形式/安全検査を維持して重複計算を減らす」範囲を提示した上で、11/11に本人が「つぎへ」と指示した。既存の通常実装判断の委任・継続的マージ許可と合わせ、限定改善の設計統合→worker実装/CI→責任者独立レビュー/修正→問題のないPR統合/APK報告へ進む。内部方式や80%等の工学目標を本人が個別精査したとは記録しない。これらの採否条件は効果を後付けしないため計測前に責任者が固定する。D057/D058の既存承認と、D031/D056の製品仕様OPENは維持する。
