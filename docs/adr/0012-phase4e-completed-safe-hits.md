# ADR-0012: 確定済み安打と明示された走者進塁の限定参照

- Status: **Accepted**、2026-10-30 日本時間。
- 関連: D004/D022/D023、D046限定CONFIRMED、D029/D031/D032 OPEN。
- 対象: [Phase 4e設計v0.1](../PHASE4E_DESIGN.md)。設計PR: [ゲームPR #31](https://github.com/thrsth45h/baseball-sim/pull/31)（本人の範囲承認済み）。
- ユーザーの明示承認: **2026-10-30、本人が設計PR #31を示した確認に「設計PR #31の範囲で進める（推奨）」と回答。全員safe・打者最終塁と安打価値が等しい限定条件、明示行先の検査と反映、旧型/step利用、固定表/列、ゲーム側Python参照/CIとworker開始を承認した。** 「つぎへ」だけを承認とは扱っていない。

## 現状・代替案

4dは半回/表裏/得点保持まで完成したが、通常の安打後の局面を入力できない。安打ごとの一律進塁、自由なafter state、走者ID/アウト/時系列までの拡張、試合終了・Android先行を比較し、裁定済みの全員safe安打と各走者の最終塁を明示する限定actionを推奨する。

## 推奨・反論と根拠

hit_bases1/2/3は裁定済み入力で、打者がその安打で得た塁に留まる場合だけを扱う。MLB2026の9.06(b)には送球間の進塁と安打価値を区別する例があり、最終塁から公式安打価値を判定しない。既存走者には据置きを許し、安打の種類だけから進塁を補完しない。

Noneと当初占有の対応、逆走・最終位置衝突・後続走者だけの先行を検査する。打者と当初塁スロットで局所的に走者を区別できるため、永続IDを先行追加しない。ただし最終位置だけでは途中の触塁/追越し/妨害等を証明できない。全員safe・裁定/正規触塁完了・失策/アウト/サヨナラ等なしを強い外部入力条件とする。

## 影響・受入れ

旧4d.stateと旧4actionを再利用し、新ResolveSafeHitはfair待ちだけでcountを消費し、指定走者の本塁到達数を攻撃側へ加点する。outs/回/side/closed累計は不変。旧code/fixture/results/flagsと研究repoは保持、新しいゲーム側Python参照/専用CIを提案する。

制御20セル・48受理表・18列/60action/78分割、18,000型正候補の288受理/17,712拒否、識別走者の独立照合と人数収支・厳密型/再現性/出力防護を受入れ条件とする。件数は新methodへ加算せず旧4suiteと別記する。D029/D031/D032はOPEN。走塁判断/確率・一般裁定・試合終了/勝敗・公式成績・研究/能力・Android採用は別判断。

## 承認後

本人が設計の限定条件・API/固定表/列・Python参照/CIとworker開始を明示承認したため正式化し、設計PRマージ後workerへ委任する。技術点検・CIを仕様承認と扱わない。
