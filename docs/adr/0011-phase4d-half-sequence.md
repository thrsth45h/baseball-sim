# ADR-0011: 表裏の切替と両チーム得点の限定参照

- Status: **Accepted**、2026-10-30 日本時間。
- 関連: D004/D022、D045限定CONFIRMED、D029/D031/D032 OPEN。
- 対象: [Phase 4d設計v0.1](../PHASE4D_DESIGN.md)。設計PR: [ゲームPR #28](https://github.com/thrsth45h/baseball-sim/pull/28)（本人の範囲承認済み）。
- ユーザーの明示承認: **2026-10-30、本人が本PRを示す確認に「設計PR #28の範囲で進める（推奨）」と回答。限定半回列制御・得点表現・明示Advance・固定表/列・ゲーム側Python参照/CI・旧型/step利用とworker開始を承認した。** 「次へ」だけを承認とは扱っていない。

## 現状と問題

4cは投球/完了プレー確定/次打者をつなぎ、三アウトで停止する。表裏を反復する際の得点の重複、加算先、塁/カウントのリセットは未実装。研究モデルや新プレーを先に接続しなくても検査できる状態管理である。

## 代替案・推奨と反証

終了判定のない合成半回列の明示制御を推奨する。旧4c.stepへ委任し、三アウト後だけAdvanceHalfを受ける。保存するのは切替済みのチーム別累計と現在halfで、表示合計は導出する。Advance前後のscoreを不変とし二重加算を防ぐ。

単打/併殺等を先に追加するとプレーの幅は増えるが、走者別時系列の契約が必要。完全試合の終了/延長は規則判断が増え、Android縦切りはD032の技術採用が伴う。現状維持より半回を重ねる骨格へ進む一方、プレーの再現性を増やす成果ではない。限定範囲を小さく完了する。

## 規則と独自契約・影響

MLB2026の通常開始/三アウト交代を参照するが、有限の合成列におけるtop/bottom/Advance/得点保存方式は試験APIの契約。試合終了判定がないため、9回以降の進行を実際の試合で許されるという意味にしない。10回以降の走者配置や架空リーグの規約も採用しない。

旧4a/b/cの型/step・source/fixture/結果/flags、研究repoを保持し、新しいゲーム側Python参照/専用CIだけを提案する。旧source7パスをimport/hashで読み、旧データ/研究モデルは新runへ入力しない。Android/DB/セーブ/公式記録/能力は未採用。外部snapshotの過去履歴、古いsnapshotの再投入/通信再送の永続重複排除は保証しない。

## 受入れ・未解決事項

制御16セル、固定16列/100action/116分割、代表96Advance、表示score不変/攻撃側だけの加算、旧4c委任、境界/厳密型/出力防護/再現性を設計正本で検査する。新旧4suite/CIを別集計し、責任者が独立レビューする。一般走塁・試合終了/延長/勝敗・研究/能力・Android技術は別判断。

## 承認後の進め方

本人が提示された限定範囲を明示承認したためD045限定CONFIRMED/ADR Acceptedとし、設計PRマージ後workerへ実装を委任する。CI・設計点検・PR作成を仕様承認に置き換えない。
