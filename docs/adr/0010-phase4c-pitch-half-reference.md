# ADR-0010: 明示的な確定アクションで投球カウントと半回状態をつなぐ

- Status: **Accepted**
- 対象: [Phase 4c設計v0.1](../PHASE4C_DESIGN.md)、D044は限定接続のみCONFIRMED。D029/D031/D032 OPENを維持。
- 設計PR: [ゲームPR #25](https://github.com/thrsth45h/baseball-sim/pull/25)。
- ユーザーの明示承認記録: **2026-10-30、本人が本PRを示す確認に「設計PR #25の範囲で進める（推奨）」と回答。** 限定接続・強い入力条件・固定表/列・ゲーム側参照/CI・旧型/step利用とworker実装開始の承認。「次へ」だけを承認とは扱っていない。

## 現状と問題

4aはカウント終端まで、4bは完了済みW/X/Hの塁・アウト・得点まで検証済み。4a statusだけを4bへ自動変換すると、走者据置き/追加進塁なし/合法本塁打等の事実を勝手に補う。結果を確定する前の更新、二重反映、次打者開始のタイミングを別契約にする必要がある。

## 代替案・推奨と反論

自動変換、明示確定による限定接続、先に一般走塁/走者IDを作る案、統計モデルも同時接続する案を比較する。明示BeginBatter/Pitch/Resolveの3actionと、count/halfから導出する4stageを推奨する。既存ルールを変更せず処理順を検証できるが、現実のプレーを裁定したり確率で生成したりする成果ではない。

## 入力条件・状態・影響

countは旧4a、halfは旧4bの不変型。終端countはResolveまで保持し、受理したResolveで旧4b.stepを1回適用してcount=Noneへ消費する。次打者は明示Begin、三アウトは残塁/得点を保持して停止。halfは最後に確定反映したsnapshotで、実世界の瞬間状態や規則上の打席終了時点を表さない。

Resolveは4aの停止status×W/X/Hの12組中5組に限定し、追加条件が完了・確定済みと外部から明示される場合だけ受理する。列の途中に未対応の盗塁/暴投/走者アウト等がない合成条件を置く。省略された現実イベントや履歴の合法性は検出できず、外部二重送信/古いcheckpoint再投入の永続重複排除も保証しない。

旧4a/4bの型/stepへ新4cから明示接続し、旧source/契約/fixture/結果/flagsは保持する。新flagsはconnected_to_phase4a/phase4b=true。依存source5パスの同一性確認と、旧データ/研究モデル非利用を区別する。Pythonは検算用でAndroid/DB/セーブは未採用。

## 受入れ・判断を求めること

制御12セル/互換12セル、18列/82action/100分割、2,304投球組合せ、互換288試行と段階違反/第三アウト/二重Resolve拒否等を設計正本に従って検証する。責任者の独立期待値/別実行、全新旧suiteとCI、出力防護/新旧保持を点検する。

本人が承認したこの限定接続・入力条件・固定表/列・ゲーム側参照/CI・旧型/step利用とworker実装開始の範囲で、D044を限定CONFIRMED、ADRをAcceptedとして設計をマージし、workerへ委任する。一般走塁・研究/能力・完全試合・Android/製品採用へ承認を拡張しない。
