# ADR-0008: カウントと限定終端のルール契約をゲーム側で参照実装する

- Status: **Proposed / 未承認**
- DECISIONS: D042 OPEN、D029/D031/D032 OPENを維持。
- 対象: [Phase 4a設計v0.1](../PHASE4A_DESIGN.md)
- 設計PR: [ゲームPR #19](https://github.com/thrsth45h/baseball-sim/pull/19)（Draft・未マージ）。
- ユーザーの明示承認記録: **未承認**。「次へ」を未提示の新仕様の承認と扱わない。

## 現状と問題

3dの合成幾何まで完了したが、実際の捕球・モデル接続・能力は未検証で、ゲーム側にはカウントを進める実行可能なルール契約もない。試合処理へ進むため、限定された投球イベントを状態へ適用する部分を先に具体化する。

## 提案・代替・反論

MLB2026規則の指定部分を参照し、裁定済みの合成8イベント→不変のカウント状態/限定終端/打球受渡し、という参照実装を作る。未捕球第三ストライクや不明入力を勝手にアウトにせず拒否する。通常ファウル・合法ファウルチップ・未捕球ファウルバント・捕球ファウル飛球を区別する。96遷移表/16列は言語非依存のfixtureとする。

仮の捕球確率追加は係数の根拠が薄く、不完全な守備判断は仮定が増える。旧3b/3dの即時接続にも母集団・方向・支持範囲の課題が残る。ルール参照実装はそれらを解決せずに検証できる利点がある。一方、完全な1打席/試合を生成できる成果ではないため、後続への受渡しと未対応を明示する。

## 配置・技術・影響

ゲームrepoの新規prototypes/phase4aへ、Python標準ライブラリだけで参照実装/fixture/unittest/専用CIを置く案。データ研究コードは研究repoに保持し、この処理へimportしない。Pythonは移植前のルール検算用で、Android/DBの製品技術を選定するものではない。D032はOPEN、確率・能力・ゲーム正式採用も未決定。

## 受入れと承認

[設計書](../PHASE4A_DESIGN.md)を正本とし、96遷移・16列・全status整合・未対応/終端後拒否・長い通常ファウル・途中処理一致・情報境界・新出力防護を検証する。本人の範囲/仮定/worker実装承認後、設計マージ→専用worker→責任者レビュー/直接修正→継続許可による統合の順。

未承認のためD042はOPEN。架空リーグの全規約、研究モデル接続、公式成績、能力、UI・セーブ、製品採用の承認へ拡張しない。
