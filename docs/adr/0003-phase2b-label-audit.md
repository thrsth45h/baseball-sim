# ADR-0003: 結果分岐の予測を追加する前に記録ラベルを監査する

- Status: **Accepted**
- 関連Issue: 設計PRで兼ねる。
- 設計PR: [ゲームPR #9](https://github.com/thrsth45h/baseball-sim/pull/9)。
- DECISIONS ID: D037（監査範囲のみCONFIRMED）。D036の既存実装・数値を保存。
- ユーザーの明示承認記録: **2026-10-28、分類・欠損の監査と説明訂正の平易な説明後、本人が「勝手に進めて良い」と回答。** 「どゆこと？」は承認と扱わず、その後の指示を根拠とする。
- 対象フェーズ: Phase 2b分類監査、`phase2b-label-audit-v0.1`

## 現状と問題

Phase 2aの計算は指定5descriptionを対象とするが、限定raw照合でhit_into_playに記録上の犠牲バントとファウル地域アウトが見つかった。「通常スイングだけ」「fair_in_playがフェアを保証する」という説明は成立しない。接触二値の既存数値・母集団は保存できるが、その意味を訂正する必要がある。

## A案・B案・現状維持

- A（推奨）: 旧契約を保存し、説明を訂正。既存processed 3年とD6指定raw 3 chunkで分類・入力欠損を監査する。次の学習対象は別承認。
- B: 記録3分類を直ちに予測する。観測予測としては可能だが、ゲームの接触後の物理分岐と同一視できない。
- 現状維持: 誤った名称・除外保証が後続設計へ伝わるため推奨しない。sac_bunt記録だけの除外では、全バントを除いた保証にもならない。

## 推奨理由、反証、トレードオフ

記録を生成現象と混同せずD022–D023へ接続するためAを推奨する。1工程増え、3標本の監査で完全分類は完成しない。データ不足で後の物理ターゲットを確定できない結論も許す。監査の合格を能力較正・分類完全性の合格にしない。

## 検証可能な事実とゲーム上の仮定

2023年の指定1 chunkでhit_into_play 2,480件にsac_bunt接頭辞4件、foul territory記述のfield_out 62件が含まれることを、責任者とworkerが別計算で確認。これは限定標本の記録上の反例で、全年度の混入率や独立裁定した真値ではない。物理イベントから記録を作る順序は既承認D022–D023。

## 影響と受け入れ基準

[設計v0.1](../PHASE2B_DESIGN.md)の入力・集計・テスト・成果物を正本とする。旧コード・機械可読結果・モデルを保持し、文書は訂正を追記する。新しい接触ラベルや能力係数、ゲームの挙動、セーブへの変更はない。worker実装後に責任者が独立レビューする。

## 判断を求めること／承認後

Aの監査・説明訂正とworker実装開始を承認済み。設計マージ後に専用領域で委任し、責任者が独立レビューする。新しい予測学習・能力較正・ゲーム統合などの採用は承認していない。
