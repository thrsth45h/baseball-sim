## 1. ユーザーへ提示する範囲

**記録に残った打球を、速さと上がる角度の組合せで72区分に分ける。二つを別々に抽選する方法と、組合せで抽選する方法を比較する。** 区分の抽選まで動く研究用プロトタイプを作る。

新しい研究対象と、既存rawの確認範囲を3標本から登録145ファイルへ広げることを相談する。取得済みデータの範囲で行い、新規取得はしない。旧Phase 1/2のコード・モデル・ラベル・数値・凍結文書と索引は保存する。

今回は連続値の打球生成、左右方向、フェア／ファウル、捕球、安打・得点、選手能力1〜20、ゲーム組込みを実装しない。これらが完成したと称さず、後の比較基準を作る。

## 2. この順序にする理由と限界

Phase 2bでは、hit_into_playが物理的フェアのみ・通常スイングのみを保証せず、EV/LAの欠損と一部推定値があることを確認した。[監査と訂正](https://github.com/thrsth45h/statcast-swing-model-v1/blob/2af9657854b70a3dd1ce3db7dd8ae296cdd8745d/reports/phase2b/label-audit/REPORT.md)

ここで記録上の3分類をそのまま守備前の分岐へ使うと、記録と生成現象を混同する。まず数値のある記録集合について、速度と角度の組合せを保つ比較基準を作る。対象選択に守備後の記録が関係するため、**この分布を全接触の守備前の生成器へそのまま接続する承認ではない**。

| 選択肢 | 利点 | 制約・今回の判断 |
|---|---|---|
| A: EV/LAの固定区分の分布と抽選 | 小さく実装でき、周辺の割合を揃えて組合せの効果を比べられる | 粗い記録集合の基準に限る。推奨 |
| B: 直ちに記録上のfoul/foul_tip/hit_into_playを予測 | 記録の条件付き予測として可能 | 守備前の物理分岐とは別。今回は保留 |
| C: 連続EV/LA・方向・捕球まで一度に作る | ゲームの1球処理に近い | 欠測・方向・バント・守備との識別と複数モデルを同時に仮定する。今回は保留 |
| D: 個人のパワー／巧打力を先に較正 | 能力表示へ近づく | 観測上の分布・選択と能力の因果効果を区別できず、D029はOPEN |

「EV/LAに関係がある」と発見するだけでは研究価値は小さい。入力契約、同じ周辺分布を持つ比較モデル、年度間の基準、再現可能な区分抽選が成果となる。J1が勝つことを完了条件にしない。

## 3. 対象母集団と記録値

対象は、承認対象のraw登録集合にある2023〜2025年R試合のうち、**descriptionがhit_into_playで、EV/LAが両方有限、EV≥0、−90≤LA≤90**の行。

```text
P(EV区分, LA区分 | 指定raw登録集合, R, hit_into_play, 今回の数値適格条件)
```

選手・球種・コースに条件付けない「指定記録集合の全体分布」であり、全接触の無条件分布とは呼ばない。旧processedの位置・球速等の適格条件は継承しない。今回の予測にそれらを使わないためであり、Phase 2aの分母を置き換える変更ではない。

- `events`のsac_bunt接頭辞も自動除外しない。対象の記録バント件数・events欠損は監査に限り集計し、完全なバント判定には使わない。
- 欠損を0へ補完せず、数値をclipしない。対象hit_into_playの除外理由は、欠損→非欠損だが数値変換不能→非有限→有限だが範囲外の順で排他的に数え、採用数との分母一致を確認する。列別の観察件数は別に示す。
- EV≥0、LAの支持域と区分は研究上の規約。データ全体の物理的な正しさを保証する品質判定ではない。EVの上限は設けず、120以上を一つの区分に置く。
- 年別に登録行数、hit_into_play数、除外内訳、採用数・到達率を出す。欠損の無作為性、直接追跡値と推定値の個別識別、選択のない能力分布を示したとは扱わない。

`launch_speed`は打球速度、`launch_angle`は角度として使う。一部未追跡打球に推定値を含むことが公式CSV文書に記されている。[Savant CSV文書](https://baseballsavant.mlb.com/csv-docs) 単位はmphと度。[EV](https://www.mlb.com/glossary/statcast/exit-velocity)、[LA](https://www.mlb.com/glossary/statcast/launch-angle)

|---|---:|---:|---:|
| 2023 | 47 | 720,684 | 0 |
| 2024 | 49 | 711,899 | 1 |

1. 固定したD6 inventoryの年度別manifest hash・登録数を計画へ含め、承認対象の入力集合を定義する。これは将来年度の実ファイルを検査済みという意味ではない。
2. 各年度を処理する時に、その年度の実manifest生バイトhashを照合する。登録ファイルを(start,end,registration)で並べ、そこに明示されたファイルのみ読む。glob等の探索・登録の書換え・追加取得をしない。
3. 読む列は `game_pk / at_bat_number / pitch_number / game_date / game_type / description / events / launch_speed / launch_angle` の9列。全登録ファイルのhash・行数・登録スキーマと必要列を確認する。空登録もhashを確認し、宣言通りの空なら許可する。
4. raw行のキー欠損・非整数・非正値・年度内のchunkをまたぐ重複、R以外・日付の登録範囲／年度との不一致は停止する。自動重複削除や都合のよい補正をしない。対象への数値除外と入力整合性エラーを分ける。
5. 評価では凍結した2023入力・実装・モデルを照合し、年度間のgame_pk／投球キー重複も拒否する。必要なら2023のキー列を読んで照合するが、モデルを再推定しない。元入力の不一致を公開参照の改変で正当化しない。

原入力は読取り専用。年度ごと・chunkごとに処理し、全年度の全列を一括結合しない。新規出力先だけを許可し、入力との重なり・既存出力への上書き・途中キャッシュからの再開は拒否する。

## 5. 固定区分と比較モデル

EVの下端は `[0,40,60,70,80,90,100,110,120]` mphの9区分。下端を含み次の下端を含まない。最後は120以上の開上限区分。

LAの下端は `[-90,-20,0,10,20,30,40,60]` 度の8区分。最後の[60,90]は90を含む。他は次の下端を含まない。配列順はEVを外側、LAを内側として72セルへ平坦化する。JSONへInfinityは書かず、下端と上限の規約を記録する。

2023の採用数N>0、セル件数n_ij、I=9、J=8、経験確率P_ij=n_ij/N、その周辺r_i・c_jを用いる。**epsilon=0.01を事前固定した数値平滑化**とする。

```text
J1 q_ij = (1-epsilon)^2 P_ij
          + epsilon(1-epsilon)(r_i/J + c_j/I) + epsilon^2/(I J)
J0 p_ij = q_i+ q_+j
```

J1は各軸へ独立に一様混合を施した同時表、J0はその同じ周辺分布の積である。両モデルの速度・角度それぞれの割合は同じで、組合せの構造だけが異なる。

```text
q_i+ = (1-epsilon)r_i + epsilon/I
q_+j = (1-epsilon)c_j + epsilon/J
q_ij - p_ij = (1-epsilon)^2(P_ij - r_i c_j)
```

両モデルは合計1、全セル正。経験表が非一様でも独立なら両者は同値。一様なセル擬似度数を足す方法では、その独立性が保存されない場合があるため、この比較では各軸独立の平滑化を使う。

区分・epsilonは未較正の研究用仮設定で、物理的測定誤差・選球眼・巧打力・パワーに対応しない。epsilonはNが増えても消えず、周辺の下限はEVでepsilon/9、LAでepsilon/8となり、希少区分を増やす場合がある。評価するのはこの平滑化済みモデルであり、結果を見て設定を変更しない。

モデルは72確率と集計から成り、打者別・球種別・位置別の係数、個票、連続EV/LAペアを持たない。セル内の数値生成・補間も行わない。95mphなど区分内の閾値やBarrel条件を、この区分表だけから正確に再現できるとは主張しない。

## 6. 年度の順序と評価

1. **2023だけ確認・学習**: 47登録の実体を照合し、対象集計とJ0/J1を作る。N=0は停止。fitは2024/2025の実manifest・metadata・Parquet・header・値・hashを読まない。公開済みD6の静的な宣言は使用可能。
2. **凍結**: 設計・全設定・実装/依存版・2023入力同一性・集計・モデル・将来年度の承認済みmanifest hashを結合して保存する。
3. **2024診断・2025再現比較**: 凍結後に各年49登録の実体を照合し、同じJ0/J1を評価する。2024で候補選択・閾値変更・再較正を行わない。入力不一致は停止し、欠けたchunkを除いて続行しない。

2025はPhase 1/2で既閲覧で、設計は既存の標本監査も踏まえている。新しい未使用holdout・前向き検証とは呼ばない。2024も今回の候補調整には使わず、追加の年度診断とする。

**唯一の主比較は2025のΔLog Loss=J1−J0。負ほどJ1が良い。** 真の区分に与えた解析的確率の自然対数を使い、対象行ごとに平均する。サンプル1回を予測確率にしない。これは同じ72区分のカテゴリ損失で、連続密度の損失ではない。正の確率を保証するためlossのclipは不要。

- 両年・両モデルのLog Loss、72クラスBrier（Σ_k(p_k−y_k)^2、真のセルだけy_k=1、他は0、クラス数で割らない）、72セルの観測割合・予測確率・差、TV=0.5Σ|予測−観測|を保存する。EV/LAそれぞれの周辺TVはJ0/J1で同値になることも確認する。二値ECEやAUCは追加しない。
- 主差の95%区間のみ、2025の対象行が1つ以上あるgame_pkを昇順に固定し、対応付き500回percentile bootstrapで求める。各回G試合からG個のindexを復元抽選し、両モデルで同じ試合の損失総和／対象数総和を使う。試合平均の単純平均にしない。
- bootstrap専用Generator(PCG64(20261028))、integersでの抽選、linear補間の0.025/0.975分位を固定。G<2や無効反復があれば区間null・理由付きで、成功例だけの選別・再抽選はしない。学習・モデル・設定は固定し、再学習や将来年度全体の不確実性を含めない。
- 評価年度の対象が空なら指標null・理由付き。主比較が定義不能なときに改善を宣言しない。2024が空でも凍結モデルは変更しない。
- 負の差は、この記録集合で2023の組合せが2025にも予測情報を持ったという結果。因果・能力・ゲームへの十分性を示さない。正やゼロ付近でも、真のEV/LAが独立とは結論しない。区分の粗さ・平滑化・年度の構成変化も影響する。

## 7. 区分の抽選・実装とテスト

承認・設計マージ後、workerへ研究側の新規 `baseball_calibration.phase3a` と専用テスト・出力を委任する。CLIは合成smoke、2023 fit、凍結後evaluate、区分sampleの段階を分ける。現行依存版を維持する。

smokeは人工fixtureだけの工程試験とし、実入力を開かず `source_kind=synthetic / trained_on_real_data=false` とする。実データfitの結果や再開キャッシュへ流用しない。

- サンプラーは凍結モデルと明示RNGから(EV区分index, LA区分index)だけ返す。description・events・ヒット/アウト・真の能力・実測連続ペアを引数に取らない。推論APIでhit_into_playを先に抽選するゲーム契約は作らない。
- PCG64、EV-majorの平坦順、乱数状態の保存・復帰を記録。同じモデル・seed・版なら同じ抽選を再現する。公開例は1モデル100,000抽選の72セル集計までとし、J0はseed20261029、J1は20261030。主評価は抽選誤差を使わない。
- 人工データで非一様な独立表→J0=J1、同じ周辺だが依存した表→組合せだけが異なること、年度で依存が変わればJ1優位を保証できないことを確認。和1・正値・周辺一致・代数恒等式を絶対誤差1e-12以内で照合する。
- 人工の依存表から100,000回を固定seedで抽選し、72セルごとの度数割合と解析的確率の最大絶対差が0.01以内であることを確認する。区分indexの入替えや、J1を誤って独立抽選する不具合を検出する試験であり、MLBの妥当性検証ではない。
- bin境界・最終上限・欠損/変換不能/非有限/範囲外の排他的分母、記録バントを自動除外しないこと、未知descriptionの非採用、キー/日付/重複/改変の拒否、空chunkと空対象をテストする。
- fitの未来ファイル非読取りをread/hash/header経路で検査。評価時の凍結モデル・学習入力・コード・版の改変拒否、結果列を特徴へ流用しないこと、再開や上書きの拒否、公開物への個票・個人パス・選手ID非出力を確認する。
- 旧研究の保護と既存300テストの回帰、必要な新テスト、人工smokeの工程検証を行う。合成結果と実データ結果を区別する。

## 8. 成果物・受入れと承認を求めること

新規成果物はplan/model/input-identity/cohort-audit/evaluation/sampling-summary/report/hashに分ける。元行・実EV/LAペア・選手ID一覧をGitへ入れず、公開は設定、年別到達率、72セル集計・確率・差、指標、区間、入力識別と再現手順に限る。`trained_on_real_data=true`と能力較正・認知識別・製品採用の未達を分ける。

責任者がworkerと別のチェックアウトでコード・集計・式・テスト・必要な実行を検証し、問題を直接修正依頼する。2回の同入力実行で、時間・資源記録を除く設定・モデル・数値が一致し、CIと公開hashが整合すれば、承認済み研究範囲のPRを継続的なマージ許可に基づき統合する。J1の勝利や製品用の効果幅は合格条件ではない。
